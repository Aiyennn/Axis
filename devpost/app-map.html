System Overview

Axis reconciles scattered student-freelancer commitments (Gmail, Canvas, GitHub, Notion, Google Calendar) into a single, mathematically grounded focus queue. The architecture strictly separates deterministic calculation (deadline proximity, calendar capacity, strictness) from LLM narrative reasoning (explanations, briefings, conversational assistance).

Follow the Priority Journey (Code Route)

Frontend/src/components/dashboard/TaskReasonModal.tsx

Entry Point: User opens a task rationale modal or modifies effort (+1h, +2h, +3h). Calls editTask() in AppContext.tsx, dispatching a patch request to the FastAPI backend.

Backend/engine/metrics.py & policy.py

The Unique Kernel: calculate_metrics() evaluates available free calendar blocks before deadlines. Calculates exact mathematical slack = capacity - effort. If effort is unknown, applies the 1.0h provisional fallback with transparent warnings. RankingPolicy assigns discrete urgency points and risk tiers.

Backend/routers/chat.py & services/chat_provider.py

AI Copilot Layer: Receives user inquiries from the floating chat bubble. Injects real task and capacity context into Gemini function tools or structured prompts. Emits natural-language explanations or falls back gracefully to offline mode if LLM credentials are absent.

To Change This, Start Here

  • Tweak Scoring Points or Urgency Weights:
    Edit SLACK_POINTS, IMPACT_POINTS, or IMPORTANCE_POINTS in Backend/engine/policy.py.
  • Add New Calendar or Email Mock Feeds:
    Update Backend/integrations/fixtures/sources.json and corresponding adapter extractors in Backend/integrations/adapters.py.
  • Adjust AI Copilot Prompt or Response Length:
    Edit GeminiChatProvider.generate() in Backend/services/chat_provider.py.
  • Modify Dashboard Hero Card Layout:
    Edit Frontend/src/components/dashboard/HeroFocusCard.tsx.

A Practice to Reuse

Separation of Deterministic Logic from LLM Generation

A common pitfall in AI app development is asking an LLM to "calculate" priority scores directly. Models hallucinate numbers, output erratic ranks, and cannot guarantee mathematical invariants (e.g. deadline compliance).

Axis Pattern: Use pure, verifiable Python code for scheduling and arithmetic (the Backend/engine/ package, validated by 81 unit tests), and restrict the LLM to reading facts and narrating human explanations. This gives users 100% predictable decision safety and transparent mathematical trust.
